Расширение Chrome Manifest V3: на странице видео поддерживаемого сайта — **YouTube, Bilibili, Dailymotion, Vimeo, Instagram, Facebook, TikTok** — **ручной клик** запускает запись. Расширение захватывает всю поверхность текущей вкладки вместе со звуком страницы, кадр за кадром вырезает с помощью Canvas **фактически отображаемую область изображения плеера (или любую выделенную вами область)** и в итоге сохраняет **видеофайл со звуком** в папку загрузок — нативно предпочитает **MP4 (H.264/AAC)**, автоматически откатываясь на **WebM**, если браузер или система это не поддерживают.

Сайт для записи распознаётся автоматически: расширение определяет сайт по домену текущей страницы и соответствующим образом переключает префикс имени файла и подпись сайта во всплывающем окне / уведомлениях (см. «Поддерживаемые сайты» ниже).

## Возможности

- **Запись на одном из семи крупных видеосайтов**: нативные видеостранницы YouTube / Bilibili / Dailymotion / Vimeo / Instagram / Facebook / TikTok записываются по единому конвейеру (tabCapture → поиск плеера → кадрирование Canvas → MediaRecorder). Текущий сайт определяется автоматически и переключает префикс имени файла и тексты; различия старых и новых плееров каждого сайта собраны в `src/shared/sites.js` и обслуживаются в одном месте (см. «Поддерживаемые сайты» ниже).
- **Ноль сторонних зависимостей**: никакого npm, никакой сборки, никакого ffmpeg, никакого перекодирования (MP4 записывается нативно через `MediaRecorder`, а не конвертируется после записи).
- **Два режима записи**
  - **Весь плеер**: автоматически определяется *фактически отрисовываемый* прямоугольник плеера (рассчитывается по `object-fit` / `object-position`), исключая чёрные полосы, поля театрального режима и оболочку плеера.
  - **Выделение области**: выделите прямоугольник в любом месте страницы и записывайте только его.
- **Абсолютно чистая картинка**: все элементы управления находятся во всплывающем окне значка расширения (отдельная страница расширения, не входящая в отрисовку захватываемой вкладки), поэтому интерфейс расширения никогда не попадёт в видео.
- **Горячая клавиша на странице**: по умолчанию одиночная клавиша `R` запускает запись в режиме ожидания и останавливает/сохраняет её во время записи. Меняется в окне → **Настройки** (поддерживаются комбинации с `Ctrl` / `Alt` / `Shift` / `Command`). Работает только на видеостранницах поддерживаемых сайтов, не перехватывает клавиши других вкладок и не конфликтует с глобальными сочетаниями браузера.
- **Страница блокируется на время записи**: полупрозрачная маска закрывает всё *вне* картинки, вырезая для неё «отверстие», блокируя прокрутку, клики и разрушительные горячие клавиши — при этом **воспроизведение/пауза, перемотка, громкость, субтитры и скорость воспроизведения остаются полностью доступными**.
- **Стабильная обрезка**: фиксированные 30 кадров/с; размер canvas фиксируется на первом кадре; прямоугольник обрезки должен оставаться неизменным 3 кадра подряд до старта записи, чтобы случайно увеличенные прямоугольники (реклама, переход в театральный режим) не попали в итоговое видео.
- **Звук не теряется**: захваченная аудиодорожка воспроизводится через `AudioContext`, не давая вкладке уйти в беззвучный режим и не создавая видео без звука.
- **«Идёт запись» видно даже в полноэкранном режиме**: при воспроизведении на весь экран картинка заполняет экран, и подсказке маски негде разместиться. Состояние тогда показывают постоянное системное уведомление и всегда поверх остальных окон статусное окно Document PiP (REC + таймер + кнопка остановки); если у картинки есть чёрные полосы, внутри них дополнительно рисуется тонкая красная рамка. Все индикаторы находятся вне захватываемой картинки и **никогда не попадают в видео**; каждый можно включить/выключить отдельно во всплывающем окне: **Настройки → Индикаторы статуса полноэкранной записи**.
- **Полный набор страховок**: обнаружение чёрного кадра DRM, автоматическая остановка и экспорт при переключении вкладки или переходе, самовосстановление при сбое heartbeat прямоугольника, автоматический повтор загрузки и аварийный выход «Сбросить и начать заново».
- **Запись запускается только кликом пользователя** — никакой скрытой фоновой записи, никогда.

## Поддерживаемые сайты

Конвейер записи (tabCapture → поиск плеера → кадрирование Canvas → MediaRecorder) идентичен на всех сайтах; отличаются только три вещи: **домены внедрения** (`content_scripts.matches` в `manifest.json`), **DOM-селекторы** для поиска плеера и **название сайта** для префикса файла / текстов. В таблице ниже перечислены текущие поддерживаемые сайты и применимые страницы:

| Сайт | Записываемые формы страниц | Примечания и ограничения |
| --- | --- | --- |
| YouTube | Видеостраницы (`youtube.com/watch…`, Shorts и т. д.) | Контент для подписчиков / платный / DRM отображается чёрным (защита браузера; см. общие ограничения ниже) |
| Bilibili | Видеостраницы (`bilibili.com/video/BV…`) | Покрыты и новый плеер bpx, и старый плеер Bilibili; сериалы и фильмы с подпиской / DRM могут отображаться чёрным; **трансляции не поддерживаются** |
| Dailymotion | Видеостраницы (`dailymotion.com/video/…`) | Если `<video>` плеера обёрнуто в iframe / shadow DOM другого источника (нечитаемо из основного документа), автоматически откатывается на поиск прямоугольника внешнего контейнера плеера |
| Vimeo | Видеостраницы (`vimeo.com/…`) | Приватные видео требуют входа и прав на просмотр |
| Instagram | Посты / Reels / Stories (открытое модальное окно), отдельные видео в ленте | Часть контента имеет воспроизводимое видео только после входа |
| Facebook | Watch / Reels / оверлеи одиночного видео / видео в ленте | Часть контента требует входа; при нескольких видео на экране автоматически выбирается «сейчас видимое основное видео» |
| TikTok | Страницы деталей видео (`tiktok.com/@…/video/…`), открытые оверлеи видео, отдельные элементы ленты «Для тебя» | При нескольких превью на экране автоматически выбирается то, что «сейчас воспроизводится / с максимальной видимой площадью» |

> **Механизм поиска**: content-скрипт определяет область записи по *реально видимому* на странице `<video>`. `src/shared/sites.js` централизованно хранит кандидатные селекторы контейнеров плеера / video для старых и новых макетов каждого сайта; при попадании в контейнер берётся его внутренний `<video>`, и из `object-fit` / `object-position` выводится фактический прямоугольник изображения (без полос, оболочки и полей). Если все кандидаты не подошли, в качестве общего запасного варианта берётся «декодированный `<video>` с наибольшей видимой площадью» (рекурсивно покрывая открытые shadow DOM). Значит, основной плеер должен отрисовывать своё настоящее `<video>` в основном документе страницы (или в читаемом открытом shadow root) — **плееры, встроенные с других страниц через iframe другого источника, не поддерживаются**; полностью самописуемые поверхности canvas / WebGL (без `<video>`) не могут быть найдены автоматически — используйте **выделение области**.

> **Общие ограничения**:
> - Видео, защищённые DRM / платной подпиской (платные фильмы, эксклюзивы подписок, контент с эксклюзивной лицензией каждой платформы), в захвате отображаются чёрным — это ограничение «защищённого контента» браузера, а не дефект расширения;
> - Для контента, требующего входа (большинство видео Instagram / Facebook / TikTok, некоторые сериалы Bilibili и т. д.), сначала войдите на соответствующий сайт в браузере;
> - Если после редизайна сайта селекторы сместились и на экране несколько видимых `<video>`, область записи по умолчанию берёт декодируемое с наибольшей видимой площадью — держите целевое видео видимым и воспроизводящимся в области просмотра.

## Архитектура (зачем нужен offscreen document)

`chrome.tabCapture` нельзя вызвать из content-скрипта, а конвейеру `video` / `canvas` / `MediaRecorder` нужен оконный контекст с DOM. Попап закрывается, как только теряет фокус, а у Service Worker нет DOM вообще — поэтому ядро записи размещается в **offscreen-документе**:

1. **content-скрипт** (не внедряет собственный интерфейс, а только сообщает данные) находит плеер на поддерживаемой странице (распознанной через `shared/sites.js`) примерно каждые ~120 мс и отправляет фактический прямоугольник картинки и базу области просмотра (CSS-размер, `devicePixelRatio`, смещение visual viewport).
2. **background** по требованию создаёт offscreen-документ и вызывает `chrome.tabCapture.getMediaStreamId()` в цепочке жеста пользователя, получая `streamId`.
3. **offscreen**-документ потребляет весь поток вкладки через `getUserMedia({ chromeMediaSourceId: streamId })` (видео + звук страницы).
4. Внутри **offscreen**: скрытый `video` воспроизводит поток вкладки → скрытый `canvas` кадрирует его кадр за кадром через `drawImage` → видеодорожка `canvas.captureStream(30)` объединяется с исходным `audioTrack` → `MediaRecorder` записывает (`video/mp4` сначала, затем последовательный откат на `video/webm`) → фрагменты собираются в Blob.
   - Преобразование координат использует **фактически измеренное соотношение** («размер захваченного кадра ÷ CSS-размер области просмотра», с contain-моделью и центрированными полями) вместо наивного `rect × devicePixelRatio` — это устраняет смещение на HiDPI-экранах и при масштабировании.
5. Offscreen-документ **не может** вызывать `chrome.downloads` напрямую: он отправляет сообщение `DOWNLOAD_FILE` в **background**, который выполняет загрузку и сообщает результат через `downloads.onChanged`.

Подробнее см. `DESIGN.md`.

## Загрузка (разработка и отладка)

1. Откройте Chrome и перейдите на `chrome://extensions`.
2. Включите **Режим разработчика** в правом верхнем углу.
3. Нажмите **Загрузить распакованное расширение** и выберите каталог `src/` этого репозитория (без сборки, компилировать нечего).

> Требования: Chrome ≥ 116 (`minimum_chrome_version`, необходимо для `chrome.offscreen`); нативный вывод MP4 требует Chrome ≥ 126. Рекомендуется последняя стабильная версия.

## Использование

1. Откройте видеостранницу любого поддерживаемого сайта (см. «Поддерживаемые сайты» выше — например, страницу просмотра YouTube, страницу Bilibili `video/BV…`, страницу деталей видео TikTok; при первом посещении обновите страницу один раз, чтобы скрипты внедрились). Держите видео нормально воспроизводящимся — видео DRM / платные отображаются чёрным, это ограничение защиты браузера.
2. Нажмите на значок расширения → во всплывающем окне нажмите **Начать запись** (держите вкладку видимой, а плеер полностью в области просмотра).
   - Если браузер / система не может создать нативный MP4 (Chrome < 126 или отсутствуют кодировщики H.264/AAC), внизу попапа поясняется, что эта сессия откатится на WebM.
   - Во время записи на значке отображается красный бейдж `REC`. Закрытие попапа не останавливает запись — просто снова нажмите на значок.
3. **Записать область** (необязательно): нажмите **Записать область** → попап закроется → перетащите прямоугольник на странице → нажмите **Записать выделение** (`Esc` выходит из режима выделения).
   - Во время записи кнопка **Стоп** автоматически размещается *вне* выделения, чтобы никогда не попасть в видео. Если выделение почти заполняет область просмотра и места не остаётся, элементы управления на странице скрываются — остановите через попап расширения или хоткей.
4. В конце нажмите **Остановить и сохранить** → файл собирается и скачивается как `Сайт-ГГГГММДД-ЧЧММСС.mp4` (префикс переключается вместе с сайтом, например `YouTube-20240908-153000.mp4`, `Bilibili-20240908-153000.mp4`; в среде отката — `.webm`).
5. **Хоткей**: нажмите стандартную клавишу `R` на поддерживаемой видеостраннице, чтобы начать запись; нажмите ещё раз, чтобы остановить и сохранить.
   - Чтобы изменить его, нажмите **Настройки** в правом верхнем углу попапа: кликните по полю клавиши и нажмите новую комбинацию, `Esc` отменяет. Изменения действуют мгновенно, перезагрузка страницы не нужна.
   - Хоткей срабатывает только тогда, когда фокус на поддерживаемой видеостраннице, и никогда внутри полей ввода (поиск, комментарии). Конфликты с сочетаниями браузера или плеера сайта отмечаются на панели настроек.
6. **Тонкая подстройка изображения** (сворачиваемый раздел внизу попапа): в редких средах (необычные комбинации масштаба, мониторы со смешанным DPI) может остаться фиксированное смещение — введите вертикальное / горизонтальное смещение в пикселях (положительное = вниз / вправо).
7. **Во время записи страница блокируется маской** (режим «весь плеер»):
   - Всё вне картинки покрыто полупрозрачным чёрным: кнопки и ссылки некликабельны, колесо и сенсорная прокрутка заблокированы, позиция прокрутки зафиксирована.
   - **Разрешено**: воспроизведение/пауза, перемотка, громкость, субтитры, скорость — всё, что является чистым управлением воспроизведением.
   - **Заблокировано**: клавиши прокрутки (Пробел, PageUp/PageDown, Home/End, стрелки вверх/вниз), полный экран `f`, театральный режим `t`, мини-плеер `i`, беззвучный режим `m`, двойной клик по картинке — эти действия меняют макет или делают аудиодорожку беззвучной.
   - У маски есть отверстие для картинки, поэтому она не покрывает ничего из записываемого и, соответственно, **никогда не появляется в выводе**; под картинкой (над ней, если не хватает места) показывается «Идёт запись · страница заблокирована».
   - Изменение размера окна браузера веб-страница запретить не может: при обнаружении изменения области просмотра на маске появляется предупреждение, а попап советует перезаписать (кадрирование могло сместиться).
8. После остановки маска автоматически удаляется, и страница возвращается в норму — без остаточных узлов и слушателей.

### Форматы вывода

| Среда | Вывод |
| --- | --- |
| Chrome ≥ 126 с кодировщиками H.264/AAC (например, свежий Chrome на Windows / macOS) | **MP4** (H.264 + AAC, `.mp4`) |
| Chrome < 126 | WebM (`.webm`) — попап поясняет причину |
| Chrome ≥ 126, но платформа без кодировщиков (некоторые сборки Linux) | WebM (`.webm`) — попап поясняет причину |

> Перекодирование не выполняется вовсе: когда MP4 доступен, он записывается нативно через `MediaRecorder` (мгновенно, без потери качества); иначе расширение откатывается на WebM.

### Разрешения

| Разрешение | Назначение |
| --- | --- |
| `tabCapture` | Ограниченное разрешение; захватывает картинку и звук текущей вкладки после клика пользователя |
| `downloads` | Сохраняет запись в локальную папку загрузок |
| `activeTab` | Временный доступ к текущей вкладке при клике на значок |
| `offscreen` | Создаёт offscreen-документ, где выполняются захват / кадрирование / запись |
| `storage` | `session` хранит состояние записи и намерение старта; `sync` хранит хоткей, подстройку изображения и переключатели статуса полноэкранной записи |
| `notifications` | Индикатор полноэкранной записи: постоянное уведомление «Идёт запись» (с кнопкой остановки) + разовое уведомление об успехе / ошибке сохранения (отключается в настройках) |

Нет `host_permissions`, нет сетевых запросов, нет сбора пользовательских данных; content-скрипт внедряется и действует только на доменах семи поддерживаемых сайтов из `content_scripts.matches` — на других сайтах не происходит ни внедрения, ни каких-либо действий.

```bash
python3 scripts/verify_extension.py
```

Покрытие: манифест / MV3 / обязательные файлы, ограничение доменов и порядок внедрения поддерживаемых сайтов (YouTube / Bilibili / Dailymotion / Vimeo / Instagram / Facebook / TikTok) (`shared/hotkey.js` → `shared/indicator.js` → `shared/sites.js` → `content/guard.js` → `content/pip.js` → `content/selector.js` → `content/countdown.js` → `content/content.js` → `content/hotkey.js`), минимальные разрешения, ноль сторонних зависимостей, синтаксис всех JS-файлов (`node --check`), границы контекстов API (content-скрипты не должны напрямую вызывать `tabCapture` / `downloads` / `offscreen`), границы внедрения на страницу (элементы управления должны находиться в попапе расширения; единственный модуль, которому разрешено создавать DOM, — `content/guard.js`, и он обязан вырезать отверстие под картинку, оставлять его пустым и быть удаляемым за сессию), а также границы модуля хоткеев.
